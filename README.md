# Resource-Constrained Multi-Protocol Sensor Telemetry

## Problem statement

> Resource-Constrained Sensor Telemetry  
> Design and implement a multi-protocol sensor node (e.g., ESP32/Arduino) measuring ambient temperature and humidity. Evaluate performance metrics including packet payload overhead, RAM usage, and battery power consumption, when transmitting sensor readings via HTTP (RESTful POST requests), CoAP (UDP-based POST/PUT), and MQTT (TCP-based publish messages to a broker).

## 1. Project overview

This project uses an ESP8266 NodeMCU sensor node with a DHT11 temperature/humidity sensor and an INA219 voltage/current/power monitor. The node can send telemetry using three selectable network protocols:

- **HTTP:** REST-style POST request to the Flask backend over TCP.
- **CoAP:** CoAP POST request over UDP.
- **MQTT:** Publish a JSON message to a Mosquitto broker over TCP. Flask subscribes to the same topic and receives the message from the broker.

The Flask application provides the backend API, receives HTTP telemetry, runs a CoAP UDP listener, subscribes to MQTT, and serves the dashboard. The dashboard displays the sensor readings and transmission-performance measurements for the selected protocol.

## 3. Hardware and Arduino IDE setup

### Hardware used

- ESP8266 NodeMCU (ESP-12E)
- DHT11 temperature and humidity sensor
- INA219 voltage/current/power sensor module

### Sensor connections

| Component | ESP8266 connection |
|---|---|
| DHT11 DATA | D4 |
| DHT11 VCC | 3V3 |
| DHT11 GND | GND |
| INA219 SDA | D2 |
| INA219 SCL | D1 |
| INA219 VCC | 3V3 |
| INA219 GND | GND |

Connect the measured supply/load through the INA219 VIN+ and VIN− terminals in series, following the wiring diagram for your INA219 module. Do not connect the measured battery/supply voltage directly to the ESP8266 3V3 pin. The firmware uses the INA219 32 V / 2 A calibration profile; check that the actual module and shunt are suitable for the circuit being measured.

### Arduino IDE libraries

Install/select the ESP8266 board package and the libraries used by the sketch:

- DHT sensor library
- Adafruit INA219
- Adafruit BusIO (dependency of Adafruit libraries)
- PubSubClient

Select the correct NodeMCU board and COM port, upload the firmware, and open Serial Monitor at **115200 baud**.

## 4. Configure Wi-Fi and laptop IP address

The ESP8266 and the laptop running Flask/Mosquitto must be connected to the same local Wi-Fi network for this setup.

### Step 1 — Find the laptop's Wi-Fi IPv4 address

On the Windows laptop:

1. Connect to the Wi-Fi network that the ESP8266 will use.
2. Open Command Prompt or PowerShell.
3. Run:

   ```cmd
   ipconfig
   ```

4. Find the section named **Wireless LAN adapter Wi-Fi** (the adapter may have a slightly different name).
5. Note the **IPv4 Address**, for example `10.176.181.174`.

Use the Wi-Fi adapter's IPv4 address, not the Default Gateway, Subnet Mask, Ethernet adapter address, or an address belonging to a virtual adapter. The example address in this README is only an example/current project setting; your address may be different.

### Step 2 — Update the firmware settings

Open `multiprotocol_sensor_node.ino` and update these definitions near the top of the file:

```cpp
const char* WIFI_SSID = "YOUR_WIFI_SSID";
const char* WIFI_PASSWORD = "YOUR_WIFI_PASSWORD";
IPAddress SERVER_IP(10, 176, 181, 174);
```

- Replace `YOUR_WIFI_SSID` with the exact Wi-Fi network name (SSID).
- Replace `YOUR_WIFI_PASSWORD` with that network's password.
- Replace `10, 176, 181, 174` with the laptop's current IPv4 address, keeping the four comma-separated numbers.

`SERVER_IP` is used by the firmware to reach the Flask server and the MQTT broker. If the laptop joins another Wi-Fi network or receives a new IPv4 address from the router, update `SERVER_IP` and upload the firmware again.

### Step 3 — Match the Flask MQTT host

In `app.py`, check the MQTT configuration near the top:

```python
MQTT_HOST = os.getenv("MQTT_HOST", "10.176.181.174").strip()
MQTT_PORT = int(os.getenv("MQTT_PORT", "1883"))
MQTT_TOPIC = os.getenv("MQTT_TOPIC", "iot/esp32/sensor").strip()
```

Set the default `MQTT_HOST` to the same laptop IPv4 address used for `SERVER_IP` in the firmware. Alternatively, set it for the current PowerShell session before starting Flask:

```powershell
$env:MQTT_HOST = "10.176.181.174"
$env:MQTT_PORT = "1883"
$env:MQTT_TOPIC = "iot/esp32/sensor"
```

Replace the example IP with the address found using `ipconfig`. Keep the MQTT topic exactly the same in the firmware and backend: `iot/esp32/sensor`.

## 5. Install the Python environment (first-time setup)

These steps are for Windows PowerShell. Run them from the project folder — the folder containing `app.py` and `requirements.txt`.

### Step 1 — Open the project folder in the terminal

In VS Code, open the project folder, then choose **Terminal → New Terminal**. Check that the terminal is in the project folder. You can confirm with:

```powershell
Get-Location
```

### Step 2 — Create a virtual environment

Run this only when creating the environment for the first time:

```powershell
py -m venv .venv
```

This creates a local `.venv` folder so the project's Python packages are kept separate from other Python projects.

### Step 3 — Activate the virtual environment

```powershell
.\.venv\Scripts\Activate.ps1
```

The terminal prompt should now start with `(.venv)`. If PowerShell blocks the activation script, allow scripts for this terminal session only, then activate again:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

If you are using Windows Command Prompt instead of PowerShell, activate with:

```cmd
.venv\Scripts\activate.bat
```

### Step 4 — Upgrade pip

```powershell
python -m pip install --upgrade pip
```

### Step 5 — Install project dependencies

```powershell
python -m pip install -r requirements.txt
```

The current `requirements.txt` installs Flask and Paho MQTT. The Mosquitto broker is a separate Windows application; it is **not** installed through pip.

You only need to create the virtual environment and install the Python dependencies once. When dependencies are changed in `requirements.txt`, activate `.venv` and run the install command again.

## 6. Install and configure Mosquitto

Install Eclipse Mosquitto for Windows separately. Official download page:

[https://mosquitto.org/download/](https://mosquitto.org/download/)

During installation, make sure the Mosquitto executable is available in PATH. Open a new terminal and check:

```powershell
mosquitto -h
```

The project folder contains `mosquitto.config`. Its contents are:

```conf
listener 1883 0.0.0.0
allow_anonymous true
persistence false
log_type all
```

This configuration makes the broker listen on port **1883** on the laptop's network interfaces, so the ESP8266 can connect using the laptop's Wi-Fi IPv4 address and Flask can subscribe to that broker. Anonymous access is enabled only to simplify testing on a trusted, private lab network. Do not expose this configuration to the public internet or an untrusted network; use broker authentication and appropriate firewall restrictions outside a controlled lab.

## 7. Start the project (two separate terminals)

The broker and Flask backend are separate processes. Keep both running while testing. The recommended order is to start Mosquitto first, followed by Flask.

### Terminal 1 — Start the Mosquitto broker

Open a new terminal and change to the project folder — the folder containing `mosquitto.config`. Run:

```powershell
mosquitto -c mosquitto.config -v
```

Keep this terminal open. The `-c` option tells Mosquitto to use this project's configuration file, and `-v` enables verbose broker logs. You should see the broker start and listen on port `1883`.

If Windows reports that `mosquitto` is not recognized, Mosquitto may not be installed or its installation directory may not be in PATH. Reopen the terminal after installation, or run `mosquitto.exe` using its full installation path.

### Terminal 2 — Activate the environment and run Flask

Open another terminal in the same project folder. Activate the virtual environment:

```powershell
.\.venv\Scripts\Activate.ps1
```

If you changed the laptop IP and are using environment variables, set `MQTT_HOST` in this same terminal before starting the backend:

```powershell
$env:MQTT_HOST = "YOUR_LAPTOP_IPV4_ADDRESS"
```

Then start Flask:

```powershell
python app.py
```

For the first run, use the same steps after completing the virtual environment and dependency installation. Keep this terminal open too. Flask starts the HTTP dashboard/API, the CoAP UDP listener, and the MQTT subscriber.

### Open the dashboard

On the laptop, open:

```text
http://127.0.0.1:5000
```

To open it from another device on the same Wi-Fi network, use:

```text
http://YOUR_LAPTOP_IPV4_ADDRESS:5000
```

Upload/run the ESP8266 firmware after setting the SSID, password and `SERVER_IP`. Select HTTP, CoAP or MQTT on the dashboard and start transmission.

### Subsequent runs

After the first-time setup, you do not need to recreate `.venv` or reinstall packages each time. For each project session:

1. Start Mosquitto in Terminal 1 using `mosquitto -c mosquitto.config -v`.
2. Activate `.venv` in Terminal 2 and run `python app.py`.
3. Power the NodeMCU and open the dashboard.

Stop the services with `Ctrl+C` in their respective terminals. Deactivate the Python environment when finished with:

```powershell
deactivate
```

## 8. Network ports and Windows Firewall

The laptop and NodeMCU must be able to communicate over the same local network. Allow the relevant ports on the Windows **Private** network profile when Windows Firewall prompts you or when connectivity is blocked:

| Port | Protocol | Purpose |
|---|---|---|
| 5000 | TCP | Flask dashboard, device configuration and HTTP telemetry |
| 1883 | TCP | Mosquitto MQTT broker |
| 5683 | UDP | CoAP telemetry listener |

Do not disable Windows Firewall entirely. Allow the required application/ports only on the trusted private network. If the laptop's Wi-Fi IP changes, update the firmware `SERVER_IP` and Flask `MQTT_HOST` as described above.

## 9. Telemetry format and dashboard readings

The firmware publishes/sends a JSON object containing fields in this format:

```json
{
  "device_id": "NODEMCU_01",
  "temperature": 29.60,
  "humidity": 34.00,
  "battery_voltage_v": 4.648,
  "battery_current_ma": -3.500,
  "battery_power_mw": 20.000,
  "sequence": 55
}
```

The INA219 fields are optional in the backend so firmware versions without INA219 can still send temperature and humidity. Current and power can be signed values; the backend accepts finite signed readings rather than treating a negative reading as a malformed packet.

The dashboard displays:

- DHT11 temperature in °C.
- DHT11 relative humidity in %.
- INA219 voltage in V.
- INA219 current in mA.
- INA219 power in mW.
- Transmission payload size, protocol overhead, estimated total bytes and sampled RAM drop.

The performance metrics are intended to compare the three protocol runs. The displayed RAM drop is the sampled decrease in free heap during transmission; it is not the total RAM installed on the board or a complete measurement of program memory use. Battery power is taken from the INA219 telemetry reading.

## 10. Verify MQTT end-to-end

A successful publish message on the ESP8266 Serial Monitor does not by itself prove that Flask received the message. Verify each stage:

1. **ESP8266:** Serial Monitor shows that it connected to the broker and attempted to publish to `iot/esp32/sensor`.
2. **Mosquitto:** Terminal 1 shows an incoming PUBLISH message on `iot/esp32/sensor`.
3. **Flask:** Terminal 2 shows that the subscription was accepted and then logs an `[MQTT RX]` message containing the sensor values.
4. **Dashboard:** Select MQTT and confirm the temperature, humidity, voltage, current and power cards update.

For an independent check, open a third terminal and run:

```powershell
mosquitto_sub -h YOUR_LAPTOP_IPV4_ADDRESS -p 1883 -t "iot/esp32/sensor" -v
```

Replace the address with the laptop IPv4 address. When the ESP8266 publishes, this subscriber should print the topic and JSON payload. Stop it with `Ctrl+C` when finished.

If the ESP8266 reports a publish attempt but neither Mosquitto nor `mosquitto_sub` shows a message, check the Wi-Fi connection, `SERVER_IP`, broker listener and Windows Firewall. If Mosquitto shows the message but Flask does not, check the Flask `MQTT_HOST`, `MQTT_PORT`, `MQTT_TOPIC`, subscriber status and any `[MQTT RX ERROR]` output. The MQTT topic must match exactly on the firmware, broker subscriber and backend.

## 11. Troubleshooting checklist

- Confirm the laptop and ESP8266 are connected to the same Wi-Fi network.
- Re-run `ipconfig` and verify the current Wi-Fi IPv4 address.
- Check `WIFI_SSID` and `WIFI_PASSWORD` in the firmware.
- Check `SERVER_IP` in the firmware and `MQTT_HOST` in the backend.
- Confirm Mosquitto is running with `mosquitto -c mosquitto.config -v`.
- Confirm the broker is listening on TCP port `1883` and the private-network firewall permits the connection.
- Confirm Flask is running and the dashboard opens at `http://127.0.0.1:5000`.
- Confirm `MQTT_TOPIC` is exactly `iot/esp32/sensor` in both firmware and backend.
- Open Serial Monitor at 115200 baud and check the ESP8266 connection/publish logs.
- Check that your existing `static/index.html` has the IDs required by `static/app.js`, including `temperature`, `humidity`, `battery-voltage`, `battery-current`, and `battery-power`.
